# 发布目录与默认同步

状态：2026-09-20。SDK 0.5.0、钉钉插件 0.3.0 已发布。

`catalog/index.json` 是数据目录；`catalog/releases/<插件>/<版本>.json` 镜像 GitHub Release
的已签名描述文件，保持逐字节相同。这里不放 wheel、源码或凭据，不执行插件。
目录内的版本路径禁止覆盖，SHA256 固定实际内容；修改内容会被平台拒绝。

目录入口：
`https://raw.githubusercontent.com/jhupo/opsmesh-plugin-center/master/catalog/index.json`。
管理员配置平台源时填当前目录文件的 SHA256，`allowed_hosts` 只需
`raw.githubusercontent.com`。为固定目录快照，可将入口中的 `master` 换成已合入的完整提交。
更新目录需重新批准目录摘要再同步，不能在后台接受未经批准的新内容。

默认只提交源的 `/sync` 请求。Worker 获取目录，生成可选插件信息；不安装、不授予发布者
信任、不创建服务凭据、不下载容器镜像、不启动插件进程。
之后的签名描述文件下载、权限与绑定预览、安装批准、隔离进程部署都必须分别明确发起。
描述文件下载也只是 JSON 验签，不执行 Python 包。

新增版本发布步骤：

1. 等版本 tag 的包、镜像、签名描述文件和来源证明全部发布成功。
2. 核验 GitHub 来源证明、实际字节摘要、发布者签名及镜像摘要。
3. 通过 PR 增加描述文件镜像和目录条目，已有版本文件不能修改或重新签名。
4. 合入后核验公开 HTTPS 返回的字节摘要，再更新平台源的目录摘要并同步。

钉钉 0.3.0 要求平台 `>=0.1.0rc10`、SDK `>=0.5,<0.6`。当前已公开的平台 rc9 安装包
不满足要求，不能作为新版插件运行验收环境。真实钉钉应用、模板发布与消息验收仍待完成。
